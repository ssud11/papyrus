The four papers

Every Papyrus theme is ink pressed onto paper — color always encodes what a token is made of. Each theme carries its own redesign idea, and one rule set keeps them a family.

The rules that hold it together

The function band

Functions and decorators sit in the green→teal band (hue ~137–187°) in all four themes — the one hue family the whole system shares.

Structure ≠ damage

Class and type colors never share the error hue. Red always means stop — never syntax.

Sacred accents

Inkwell's violet and Noir's hot ember mark self/this — and in Inkwell, violet is also Claude's own voice in the terminal. Rare by design; that's what makes them read.

The glow rule

TUI shimmers glow in-family. In Inkwell — the one cool theme — an amber sheen has exactly one meaning: caution.

Contrast is budgeted

Content tokens ≥ 4.5:1 · structural ≥ 3.0 · comments and punctuation deepened to ≥ 5.0. Legibility by arithmetic, not vibes.

The warm rule

No blue, purple, or magenta in everyday roles — QD-OLED panels show no subpixel fringe. Two documented exceptions: Inkwell's cool palette, and the spectral identity slots (subagents, the ultrathink rainbow).

Beyond the editor

The same pigments run through the Claude Code TUI — spinner, prompt borders, diff tints, subagent slots — and a matching status line: model, branch, account, context meter, cost, all in theme ink.

Get Papyrus

VS Code

Search “Papyrus” in the Extensions panel, or via the command palette:

ext install SS-inkwright.papyrus-inkwright

Claude Code TUI

The repo doubles as a Claude Code plugin marketplace:

claude plugin marketplace add ssud11/papyrus
claude plugin install papyrus@papyrus
